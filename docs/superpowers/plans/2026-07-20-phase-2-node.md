# Node Phase 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Clean-slate rewrite of `@dagsocial/node` against Phase 2 contracts — dual-ledger HTTP node with challenge-response PoW, UTXO engine, ordering blocks, likes, invites, stump pruning, and SQLite storage.

**Architecture:** Express HTTP server over a 3-layer stack: `store/` (SQLite via better-sqlite3, table-prefixed), `services/` (verifier, PoW, UTXO engine, block creator, stumps, invites, likes), `routes/` (Express handlers). All shared types from `@dagsocial/types`. Fresh schema — no Phase 1 migration.

**Tech Stack:** Node.js ≥ 22, TypeScript, Express, better-sqlite3, cbor-x, Vitest, tsup

## Global Constraints

- Node.js ≥ 22 — `createHash('blake2b512').subarray(0, 32)` for all 32-byte hashes
- `@dagsocial/types` Phase 2 built and importable (63 tests green)
- Secret keys never in API responses or DTOs
- `post.id` computed server-side via `computePostId()` — client-submitted IDs ignored
- Protocol version on all wire types (currently 1, will be 2 at release)
- Content limit 1–300 UTF-8 bytes, parent refs 0–8
- Signatures raw Ed25519 (64 bytes), verified with `crypto.verify(null, ...)` using KeyObject
- Wire format: CBOR via `cbor-x`. HTTP API: JSON
- UTXO transactions atomic — all boxes consumed/created in one commit
- Karma decay applied at box consumption time
- Sub-block identity IS post identity (`computePostId`)

```sql
-- Identity (carried forward)
CREATE TABLE IF NOT EXISTS identities (
  user_id TEXT PRIMARY KEY,
  public_key BLOB NOT NULL,
  created_at INTEGER NOT NULL DEFAULT (unixepoch())
);

-- Challenges
CREATE TABLE IF NOT EXISTS challenges (
  user_id TEXT PRIMARY KEY,
  challenge BLOB NOT NULL,
  expires_at_block INTEGER NOT NULL
);

-- Posts DAG
CREATE TABLE IF NOT EXISTS dag_posts (
  id TEXT PRIMARY KEY,
  content TEXT NOT NULL,
  author TEXT NOT NULL,
  parent_refs TEXT NOT NULL,       -- JSON array of PostId strings
  challenge BLOB NOT NULL,
  pow_nonce INTEGER NOT NULL,
  protocol_version INTEGER NOT NULL,
  timestamp INTEGER NOT NULL,
  signature BLOB NOT NULL,
  raw_cbor BLOB NOT NULL,          -- Canonical CBOR bytes
  status TEXT NOT NULL DEFAULT 'pending',  -- 'pending' | 'confirmed' | 'pruned'
  block_height INTEGER             -- NULL until confirmed
);

CREATE TABLE IF NOT EXISTS dag_parent_refs (
  post_id TEXT NOT NULL,
  parent_id TEXT NOT NULL,
  PRIMARY KEY (post_id, parent_id)
);

-- Stumps
CREATE TABLE IF NOT EXISTS dag_stumps (
  id TEXT PRIMARY KEY,
  root_post_hash TEXT NOT NULL,
  subtree_merkle_root BLOB NOT NULL,
  author_id TEXT NOT NULL,
  prune_signature BLOB NOT NULL,
  karma_deltas TEXT NOT NULL,      -- JSON array of KarmaDelta
  reply_count INTEGER NOT NULL,
  upvote_count INTEGER NOT NULL,
  trigger TEXT NOT NULL,
  protocol_version INTEGER NOT NULL,
  compacted_at_block_height INTEGER NOT NULL,
  raw_cbor BLOB NOT NULL
);

-- UTXO boxes
CREATE TABLE IF NOT EXISTS utxo_boxes (
  id TEXT PRIMARY KEY,
  box_type TEXT NOT NULL,           -- 'karma' | 'credit' | 'like' | 'invite' | 'bond'
  value INTEGER NOT NULL,
  created_at_block INTEGER NOT NULL,
  spent_at_block INTEGER,           -- NULL = unspent
  owner BLOB,                       -- 32-byte public key (NULL for like/invite boxes)
  guard TEXT NOT NULL,
  proof_source TEXT,                -- PostId | StumpHash | InviteTxId | block height
  extra_data TEXT,                  -- JSON for box-specific fields (secretHash, likerId, targetPostId, etc.)
  last_touch_block INTEGER          -- For karma boxes only
);

-- Free likes (beyond LIKE_FREE_THRESHOLD * LIKE_THRESHOLD)
CREATE TABLE IF NOT EXISTS dag_likes (
  id TEXT PRIMARY KEY,
  target_post_id TEXT NOT NULL,
  liker_id TEXT NOT NULL,
  created_at INTEGER NOT NULL DEFAULT (unixepoch()),
  processed INTEGER NOT NULL DEFAULT 0,  -- 0 = pending, 1 = processed at epoch
  UNIQUE(target_post_id, liker_id)
);

-- Sub-blocks
CREATE TABLE IF NOT EXISTS sub_blocks (
  sub_block_id TEXT PRIMARY KEY,
  post_id TEXT NOT NULL,
  post_cbor BLOB NOT NULL,
  like_box_ids TEXT NOT NULL,       -- JSON array of BoxId
  producer_id TEXT NOT NULL,
  protocol_version INTEGER NOT NULL,
  status TEXT NOT NULL DEFAULT 'pending',  -- 'pending' | 'confirmed'
  block_height INTEGER
);

-- Ordering blocks
CREATE TABLE IF NOT EXISTS ordering_blocks (
  height INTEGER PRIMARY KEY,
  hash TEXT NOT NULL UNIQUE,
  prev_block_hash TEXT NOT NULL,
  sub_block_refs TEXT NOT NULL,     -- JSON array
  like_box_ids TEXT NOT NULL,       -- JSON array
  utxo_tx_ids TEXT NOT NULL,        -- JSON array
  stump_ids TEXT NOT NULL,          -- JSON array
  validator_id TEXT NOT NULL,
  validator_signature BLOB NOT NULL,
  epoch_tally_results TEXT,         -- JSON, nullable
  protocol_version INTEGER NOT NULL,
  created_at INTEGER NOT NULL
);
```

### Task 3.3: UTXO engine

**Files:**
- Create: `packages/node/src/services/utxo-engine.ts`
- Test: `packages/node/test/services/utxo-engine.test.ts`

**Interfaces:**
- Consumes: `KARMA_DECAY_RATE`/`KARMA_DECAY_GRACE_BLOCKS`/`KARMA_FLOOR` from `@dagsocial/types`, store utxo module, `computeBoxId` from `@dagsocial/types`
- Produces:
  - `validateAndApplyTx(tx: UtxoTransaction, currentBlockHeight: number): { valid: boolean; error?: string }`

**Stateless validation:**
1. All input box IDs exist and are unspent
2. Total value in = total value out (karma conservation)
3. Every consumed box's guard is satisfied: `owner_signature` → signature present for correct public key; `epoch_tally` → reject (only ordering block can consume); `hash_preimage` → reject in tx validation (handled by claim route); `inviter_signature` → signature present for inviter
4. No duplicate input box IDs
5. Box type transitions are legal (see contract)

**Stateful validation:**
1. Karma decay: `age = currentBlockHeight - box.createdAtBlock; graceAge = max(0, age - KARMA_DECAY_GRACE_BLOCKS); decay = floor(value * KARMA_DECAY_RATE * graceAge); effectiveValue = max(value - decay, KARMA_FLOOR)`
2. Created karma box value ≤ consumed karma box effective value (minus any invite/bond/like split)

**Apply:** consume all inputs (set spent_at_block), insert all outputs (compute box IDs), update indexes.

**Tests (in-memory SQLite):**
- Valid karma→karma transition (balance change only, same owner)
- Valid karma→karma+invite+bond transition (invite creation)
- Valid karma→karma+like transition (like cast)

### Task 3.4: Block creator

**Files:**
- Create: `packages/node/src/services/block-creator.ts`
- Test: `packages/node/test/services/block-creator.test.ts`

**Interfaces:**
- Consumes: `OrderingBlock`/`SubBlock`/`LikeBox` from `@dagsocial/types`, store modules (subblocks, ordering, likes, utxo, posts, stumps), `EPOCH_BLOCKS` from `@dagsocial/types` + config
- Produces:
  - `startBlockCreator(config: Config): void` — start timer + sub-block listener
  - `stopBlockCreator(): void` — stop timer
  - `onSubBlockReceived(): void` — signal new sub-block (trigger count-driven creation)
  - Internally: `createOrderingBlock(): OrderingBlock | null`

**Block creation flow:**
1. Collect pending sub-blocks (up to MAX_SUB_BLOCKS_PER_BLOCK, oldest first)
2. Collect standalone like boxes (unprocessed, no sub-block to ride)
3. Deduplicate likes: a like box appearing in both a sub-block sidecar and standalone pool is included only once
4. Collect pending UTXO transactions
5. Collect pending stumps
6. If `currentHeight % EPOCH_BLOCKS === 0`: run epoch tally:
   - Collect unprocessed locked like boxes (`getUnprocessedLockedLikeBoxes`)
   - Collect unprocessed free likes (`getUnprocessedFreeLikes`)
   - Group by targetPostId — total = locked + free
   - Author reward: `min(floor(total / LIKE_THRESHOLD), LIKE_MAX_AUTHOR_REWARD)` — mint karma to post author
   - For each locked like box: refund = 1 if total ≥ LIKE_THRESHOLD, +1 if total ≥ 2×LIKE_THRESHOLD (max 2). Net = -LIKE_COST + refund. If net == 0, return full 2 karma to liker. If net < 0, like box consumed, difference burned.
   - For each free like: mark as processed (no karma movement)
   - Consume all processed locked like boxes, mark free likes processed
   - Record EpochTally in ordering block
7. Compute block hash (blake2b512 over serialized block body)
8. Sign with validator's Ed25519 key (generate one at startup, store in memory)
9. Store block, confirm sub-blocks/posts
10. Return block or null if nothing to confirm

**Tests:**
- `createOrderingBlock` returns null when nothing pending
- Pending sub-block triggers block creation
- Block includes sub-block refs
- Sub-block confirmed after block creation
- Epoch tally runs only at epoch boundaries (height % EPOCH_BLOCKS === 0)
- Epoch tally processes locked + free likes, computes correct author reward
- Liker refund: 0 (<5 likes), 1 (5-9), 2 (≥10)
- Free likes don't generate refunds (already free)
- Deduplication: like in both sub-block sidecar and standalone appears once
- `getCurrentHeight` increments after block creation
- Block hash is deterministic for same content
